# Brand Discovery Interview

Turn founder answers into a usable brand guide while preserving the difference between intended identity, current delivery and customer evidence. This is an instruction-only workflow; it does not require scripts, browsing or a council connection.

## Choose the operation

Use the user's request and visible interview state to choose **start**, **resume**, **synthesize** or **reconcile**. Do not restart an interview simply because the skill was invoked again. If the requested operation is ambiguous and would change existing progress, ask one focused clarification.

- **Start:** Use the supplied brand and participant labels. If the brand is missing, ask for it as an unnumbered setup question. Default to 100 main questions and the label "Founder 1"; honour an explicitly requested different count. Do not collect a setup form when the user has already supplied enough to begin. The opening main question is: "What was the original reason for starting {brand}?" If founding is inapplicable to the respondent, ask one equivalent question about the brand's purpose.
- **Resume:** Inspect the supplied checkpoint and newer visible messages. Continue a pending follow-up first, then a pending main question, otherwise ask the next unaddressed main question. A follow-up keeps its original main number. If records conflict or the cursor cannot be established, ask for the specific missing/corrected state. Do not reconstruct unavailable answers or reset to Question 1.
- **Synthesize:** Use accessible records to produce the guide. Normally do this after all main numbers have been addressed; honour an early-guide request with an explicit partial label, counts and gaps. A completed sequence can still contain unknowns or skipped questions. Never report them as answered or verified.
- **Reconcile:** Compare independently captured perspectives only when requested and supplied. Match them by theme, not question number. Preserve disagreements for the founders to decide; do not invent collective approval.

For start or resume, read [interview and checkpoints](references/interview-and-checkpoints.md). For synthesis or reconciliation, read [guide and reconciliation](references/guide-and-reconciliation.md); also read the checkpoint reference if record continuity needs repair.

## Interview invariants

- Ask one focused question per interview response and wait for its answer. Label a main question "Question N of T". Do not hide several tasks in one question or reveal the full questionnaire.
- Adapt to useful threads. Keep clarifications under "Follow-up to Question N"; do not increment the main count. Stop at the agreed target rather than adding filler or Question T+1.
- Preserve raw replies and revisions separately from summaries. Treat "I don't know" as unknown and an explicit skip as skipped. A pending clarification does not silently count as addressed. The user can pause, shorten or end the interview.
- Treat the respondent's perspective as independent until they request comparison. Do not ask for the other founder's answers during independent discovery.
- Distinguish the founder's personal writing preferences from the voice the brand should use with customers. Use concrete, same-message calibration samples later in the interview.
- Challenge unsupported claims and material contradictions with reasons, not performative disagreement. Ask for examples and evidence without demanding certainty the respondent does not have.

## Evidence and scope

Separate **reported current facts**, **supplied evidence**, **aspirations**, **preferences**, **inferences** and **unknowns**. A founder's report or agreement among models does not independently verify business facts or customer demand. Link conclusions to participant-labelled question records and sources that are actually available.

When only compact checkpoint state is available, label its progress as checkpoint-reported and its conclusions as summary-derived. A referenced question ID does not establish access to that question's verbatim reply.

Do not assume services, prices, demographics, positioning, visual style, credentials or results. Brand-specific rules such as real-footage-only content belong in the user's configuration, not the generic defaults. Record relevant claim, privacy, consent and approval boundaries without inventing a regulatory policy.

Do not publish, schedule or message people as part of this workflow. Save interview files only within the user's requested scope and authorised location. For external review, use actual connected tools only when authorised; minimise private material, disclose unavailable reviewers, and never roleplay models as independent advisers. External review is optional, not a prerequisite for conducting the interview.

## Finish honestly

Provide a saveable checkpoint every 10 addressed main questions and at a pause or final boundary. In conversation-only environments, ask the user to save it outside the chat. Do not promise permanent memory or file access. A compact checkpoint can support continuation; a complete verbatim archive requires the actual transcript blocks.

Keep each founder guide provisional pending reconciliation and customer validation. If evidence or archive blocks are missing, name the gaps and offer the supported partial result; do not fabricate an archive, consensus or effectiveness claim.
